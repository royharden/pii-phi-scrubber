# Lock before held-out access

For current offline preparation, use [readiness requirements](readiness-requirements.md).
The generated `readiness-schema.json` and missing-evidence fixture are
`ExperimentReadiness/v1` data, never an experiment lock or execution approval.

The JSON is an unapproved edition template, not a locked experiment or permit.
Fill immutable model/tokenizer/weights/license/config pins, ancestry components,
sampling proportions, seed, normal/challenge taxonomy, class thresholds, cost cap,
hardware context and dev-justification evidence before independent custody seals
an edition. Require at least 20 independent test ancestry components after merging
shared lexicons, identifier grammars and scenario/template derivations. Different
seeds do not establish independence. Keep test specifications and gold outside
detector/training access. Obtain nonauthoring audit of custodian work.

Select thresholds using development only under the same rule for base/fine arms.
Lock numerical targets and report selection uncertainty; no target here is a proven
privacy floor. Keep same model family/tokenizer/decoder/label descriptions across
base and fine arms, with fine-tuning as the intended intervention. Cap trials at
three and retain failed/OOM cost receipts. Smoke configuration never proves training.

Use identical record hashes and intended denominator for all arms. Score exact
triples before renderer union. Attempted failures receive empty predictions for
coverage-adjusted quality; fully unrun arms remain not_measured with null metrics.
Show per-class precision/recall/F1, leak/overredaction/availability, normal/challenge
slices and paired block uncertainty. Unsupported/failed inputs stay visible.
Publication suppression cannot improve detector scores. Retain negative results.

Open held-out once per edition. Changes informed by its results require a fresh
independent edition, preserving the old result. No content repair retries; at most
one declared transient transport retry, retaining all attempt costs/liabilities.
Actual permits, licensed artifacts, training, four-arm execution, custody audit
and independent product acceptance remain open.
# Locked evaluation source

`m7.experiment.LockedEdition` is the immutable future execution boundary. It pins
the full intended record/hash population, all four arm configurations and external
custody/audit/pre-test-selection/authorization receipts. A development template is
never converted into a lock by running a shape validator. See
[the lifecycle and authority contract](../../docs/experiment.md). No executed lock
or sealed result has been created by source construction.
